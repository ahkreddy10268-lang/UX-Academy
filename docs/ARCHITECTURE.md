# Architecture

## Stack

| Concern | Choice | Why |
|---|---|---|
| Framework | Next.js 16 App Router, Cache Components on | Static prerender of every page; React Server Components keep content out of client bundles |
| Language | TypeScript (strict) | Content is typed data; schema errors surface at build |
| Styling | Tailwind v4 + CSS custom-property tokens | One token file (`app/globals.css`), light/dark via `data-theme` |
| Validation | zod 4 | Single schema for authoring types and runtime validation |
| Search | MiniSearch (client) over a static `/search-index.json` | Fast full-text search without a server; index loaded on first use |
| Tests | Vitest (unit/content), Playwright scripts (browser) | |
| Fonts | `next/font/google`: Newsreader, IBM Plex Sans, IBM Plex Mono | Self-hosted at build time |

No backend, database, auth or API keys. Dependencies: `next`, `react`, `zod`, `minisearch` (+ dev tooling).

## Layout

```
app/                      routes (all prerendered via generateStaticParams)
  library/[slug]          entry page OR honest planned-topic page
  formulas/[id] labs/[id] learn/[id] compare/[id] practice/workshops/[id] topics/[domain]
  search-index.json/      static GET route handler → search documents
components/
  shell/  ui/  entry/  formula/  labs/  practice/  graph/  library/  learn/  me/  search/
content/                  ALL educational data (see CONTENT_MODEL.md)
lib/
  content/schema.ts       zod schemas = the content contract
  content/index.ts        loader: parse, index, derive graph & formula library
  content/{rich,context,labels,coverage,search}.ts
  formulas/               pure, unit-tested maths (math, pointing, questionnaires, stats, visual)
  store/store.ts          local-first learner store (useSyncExternalStore + localStorage)
  store/local.ts          small localStorage values (theme, lab tallies)
scripts/                  content index, source verification, docs generation
tests/                    content quality gate; browser scripts
```

## Data flow

1. Content files export typed objects (`defineEntry`, `defineSources`).
2. `scripts/generate-content-index.ts` writes `_index.ts` aggregators (deterministic).
3. `lib/content/index.ts` parses everything with zod once per server process. Invalid content throws with a precise path → build fails.
4. Server components render pages; client components receive plain serialisable props (link maps, questions), never the whole library.
5. Rich text (`**b**`, `*i*`, `` `c` ``, `[[slug]]`, `{{src:id}}`) is tokenised by `lib/content/rich.ts` — no HTML is ever parsed from content.

## Knowledge graph

Edges = each entry's `prerequisites` (rendered as `prerequisite-of`) + typed `relations` (each with an explanatory note). Targets may be planned taxonomy slugs. The graph view uses a deterministic Fruchterman–Reingold layout (no dependency) and always ships a text list alternative.

## Personal data

`lib/store/store.ts`: one versioned JSON document under `ux-academy:v1` (bookmarks, notes, history, progress per level, quiz history, Leitner cards, saved calculations, collections, workshop responses, lab runs, preferences). `migrate()` tolerates partial/older shapes; export/import is JSON, notes also export as Markdown. Server snapshot is always the empty state, so prerendered HTML never depends on personal data.

## Next.js 16 specifics learned

- `params` is a Promise; use `PageProps<"/route">` types (generated by `next typegen`, run in `npm run typecheck`).
- `dynamicParams` is not allowed with Cache Components — unknown slugs call `notFound()` (rendered with status 200 under streaming; see ROADMAP known issues).
- Client components must not read the clock during prerender — use a `useSyncExternalStore` snapshot (see `components/me/dashboard.tsx`).
- `useSearchParams` requires a `<Suspense>` boundary.
- Theme is applied before paint by an inline script in `<head>` (no flash).

## Testing strategy

| Layer | What | Where |
|---|---|---|
| Content quality gate | schema, unique ids, valid links/citations/relations, ≥1 primary ref, quizzes have exactly one correct answer, published ⇒ all gates true, DOI verification not failed | `tests/content.test.ts` |
| Formulas | every function vs statistical tables & published worked examples | `lib/formulas/formulas.test.ts` |
| Store | migration, import/export | `lib/store/store.test.ts` |
| Browser | route crawl (status, console, failed requests); 42 interaction checks; axe-core WCAG 2.2 AA in light & dark | `tests/browser/` |
| Build | `next build` prerenders and type-checks everything | |
