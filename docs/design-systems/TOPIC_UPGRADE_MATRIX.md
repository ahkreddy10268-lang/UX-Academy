# Design Systems — 29-topic upgrade matrix

> Phase 2 planning baseline, 2026-11-24. This matrix describes what to deepen, not a claim that every lesson is deficient in every listed area. Retain strong existing material. No new taxonomy topics or slugs are proposed.

| # | Topic / canonical slug | Keep and build on | Add or deepen | Practical proof / decision task |
|---:|---|---|---|---|
| 1 | Design System — design-system | Existing definition, architecture, use/non-use, governance and examples | Historical evolution; system-as-product model; adoption cost; reference-system comparison; what a system is not | Decide whether three organisations need a full system, lightweight kit or none; defend investment |
| 2 | Atomic Design — atomic-design | Five-level model, interface inventory and alternatives | Origin and reception; boundaries that stop helping; feature-based and compound-component alternatives | Decompose one screen two ways and justify the useful model |
| 3 | Design Language — design-language | Principle-to-language model and reference cases | Brand voice, motion, interaction grammar, content tone, localisation, platform difference and evolution | Define three principles and show effects on colour, type, motion and content |
| 4 | Design Tokens — design-tokens | Existing layers, DTCG coverage, Token Lab and exercises | Token versus variable; worked DTCG file and transformed outputs; Figma variables; alias resolution; naming alternatives; accessible pair validation; pipeline and migration | Repair hard-coded/primitive-leaking tokens, export a theme and justify two-tier versus three-tier architecture |
| 5 | Primitive Tokens — primitive-tokens | Raw scales and naming material | Palette/scale construction; values and types; naming taxonomy; source data; exceptions; transforms and lifecycle | Build primitives from sample needs; identify overfitting, duplicates and unsafe assumptions |
| 6 | Semantic Tokens — semantic-tokens | Role-to-value model, resolver and Token Lab | Role taxonomy; surface/content pairings; state roles; component alias boundaries; high contrast; fallbacks and alias cycles | Repair a semantic map that breaks themes; justify each role |
| 7 | Theme Architecture — theme-architecture | DTCG Resolver, modes and Token Lab | Theme axes versus combinatorial explosion; precedence, fallback, runtime/compile-time, user preference, brand and density | Resolve light/dark/high-contrast/brand contexts and diagnose conflicts |
| 8 | Multi-Brand Systems — multi-brand-systems | DTCG, Fluent, Carbon and brand override map | Shared core versus extensions; white-label; governance; independent brand identity; QA and localisation | Design a two-brand architecture and decide what remains shared |
| 9 | Spacing Scales — spacing-scales | Scales, optical correction and references | Grid relationships; density; fluid spacing; content exceptions; platform units; optical versus mathematical systems | Repair inconsistent screens and justify off-scale values |
| 10 | Typography Scales — typography-scales | Type ramps, platforms and accessibility | Fixed/modular/fluid ramps; variable fonts; scripts/localisation; Dynamic Type; responsive reading measures | Build editorial and dashboard type with enlargement and responsive checks |
| 11 | Colour Systems — colour-systems | Colour models, roles and WCAG | Palette generation; perceptual spaces; contrast pairs; state/data colours; colour-vision differences; modern CSS colour; brand constraints | Compare two role maps; repair contrast and non-colour-signalling failures |
| 12 | Elevation Systems — elevation-systems | Surface/z-axis model and platform comparison | Shadow versus tonal elevation versus stroke; dark theme; overlays; stacking contexts; reduced visual depth | Choose elevation for card, menu, modal and sticky surfaces without relying only on shadow |
| 13 | Icon Systems — icon-systems | Sets, weights, labels and licensing | Recognition testing; optical alignment; localisation and cultural metaphors; icon versus text; fallback and platform sets | Replace ambiguous icon-only actions and define a cross-platform contract |
| 14 | Responsive Systems — responsive-systems | Responsive scales, breakpoints and containers | Fluid versus breakpoint versus container rules; content transitions; density; reflow; zoom; responsive tables/navigation | Transform a desktop screen at content-defined widths and justify each structural change |
| 15 | Component Libraries — component-libraries | Design/code lifecycle and examples | Native versus cross-platform; styled versus unstyled; ownership, distribution, extensions, dependencies and adoption cost | Choose build/buy/adopt/extend and define parity checks |
| 16 | Component Architecture — component-architecture | Anatomy, hierarchy, composition and accessibility | Compound, slots, render props, headless/styled/native; composition versus configuration; API stability | Correct a brittle API and design its contract for designers and engineers |
| 17 | Variants — variants | Variant dimensions, naming and combination handling | Variant versus state versus separate component; explosion; boolean versus enumerated props; compound variants | Reduce a bloated variant matrix without losing meaningful choices |
| 18 | Component Properties — component-properties | Figma/code property mapping and typing | API naming, defaults, slots, constraints, invalid states, controlled/uncontrolled properties and documentation | Write a full property contract and identify impossible combinations |
| 19 | Component State Management — component-state-management | State model and async-state lab | State machines and transitions; event sources; focus/announcement; recovery; platform semantics | Find missing state transitions and specify keyboard/assistive behaviour |
| 20 | Data Tables — data-tables | Table/grid semantics, async states and examples | Sorting/filtering; pagination versus virtualization; responsive strategies; bulk actions; selection; large data and empty/error states | Choose native table versus grid versus cards for tasks and specify keyboard behaviour |
| 21 | Empty States — empty-states | Empty-state types and content relationships | First-use, no-results, permission, disconnected, failure and completion; next action and recovery | Rewrite states and match the action to the cause |
| 22 | Loading States — loading-states | Determinate/indeterminate, progress and state lab | Optimistic UI, streaming, estimates, cancellation, long-running tasks, reduced motion and status messages | Select feedback for immediate, uncertain and long waits |
| 23 | Error States — error-states | Typed failures, safe retries, preservation and recovery | Validation/transient/permanent/crash; idempotency; rollback; fault containment; telemetry | Diagnose a failed booking flow and specify message, retry, preserved data and validation |
| 24 | Skeleton Screens — skeleton-screens | Practice-based evidence and async-state connection | When placeholders help or distract; shimmer/static; layout stability; progress honesty; reduced motion; evidence quality | Compare skeleton, spinner and no-placeholder for three wait profiles |
| 25 | Progressive Loading — progressive-loading | Existing lazy/progressive delivery | Priority/dependencies; streaming; pagination/load-more/infinite scroll; preserved position; web performance; offline/failure | Choose strategy for feed, article and comparison tasks |
| 26 | Design Governance — design-governance | Centralised/federated/hybrid, GOV.UK criteria and lifecycle | Decision rights; contribution/RFC; exceptions; conflict resolution; funding/service levels; community health | Write a governance charter and decide a disputed proposal |
| 27 | Design System Versioning — design-system-versioning | SemVer, migration and deprecation guidance | Token/component release cadence; pre-releases; compatibility matrix; codemods; migration communication | Classify release changes and write a migration plan |
| 28 | Design QA — design-qa | Lint, visual, interaction and accessibility QA | Design-code parity; coverage strategy; screenshot baselines; automation limits; localisation, zoom, device and assistive checks | Build a release gate and explain what automation cannot prove |
| 29 | Design System Audits — design-system-audits | Inventory, prioritisation and maturity limitations | Adoption versus quality; design debt; duplicates/unused components; a11y sampling; analytics; measuring impact without fake ROI | Audit a fictional product estate, rank findings and propose remediation |
